# 首轮真实答复评审

本轮使用 `evals/evals.json` 的 3 个情境，每个情境分别生成一次带技能答复和一次基线答复，共 6 份。评审逐条核对各答复的 5 个预定义断言，证据及行号保存在各运行目录的 `grading.json`。这是对已生成答复的文本与算术核查，没有执行其中的学习项目。

| 情境 | with_skill | without_skill | 观察到的差异 |
| --- | ---: | ---: | --- |
| 模拟研一，12h/周 | 5/5 | 4/5 | 基线四周均排满12h，没有明确缓冲；带技能为9.5h任务+2.5h缓冲 |
| 未定向，无EDA/板卡，6h/周 | 5/5 | 4/5 | 基线四周均排满6h，没有明确缓冲；带技能为4.8h任务+1.2h缓冲 |
| 证据边界与8h重排 | 5/5 | 5/5 | 两组均拒绝虚构LVS/量产，提供诚实简历及有缓冲的计划 |
| 合计 | 15/15（100%） | 13/15（86.7%） | 仅两个缓冲断言产生差异 |

预算逐项加总正确。模拟带技能的四周依次为 `3+4.5+2`、`3+4.5+2`、`2.5+5+2`、`3+4.5+2`，各9.5h；加2.5h缓冲后均12h。低时间带技能每周 `1.5+2.5+0.8=4.8h`，四周任务19.2h、缓冲4.8h，总24h。重排情境带技能 `2+2.8+1.6+1.6=8h`，备用 `2+1.2+0.8=4h`；基线为7h任务+1h机动，总8h。三份带技能答复中按分钟安排的“今天/现在”动作均已说明计入原预算。前两份基线的失败原因是缺少明确缓冲，不是任务小时相加超限。

六份答复都没有把未测能力当作已掌握，没有虚构现有商业PDK、板级、LVS、流片或量产成果。无工具情境都提供可先执行的手算/Python/纸面或代码检查支路，并说明这些证据不能替代后续仿真或硬件验证。前四周和下周计划均有实际产物与验收。基线已经能满足多数要求；证据重排情境的基线全部通过，不能声称技能在这个情境提高了效果。

断言之外有三点值得继续测试：

- 带技能答复提到“已查到岗位”“入口已核查”。评审时材料只有最终答复和情境元数据，缺少检索转录，所以没有把这些过程主张算作已证实，也没有编造工具、token或时间数据。若岗位来源是验收重点，应提供实际检索证据并单独评分。
- 情境3带技能答复的“减半输入幅度、同一稳态窗口比较”应先确认原工程的分析类型；当前用户也可能只有AC曲线。先重跑和证据归档的任务仍满足既有断言，故不为了区分组别而追加失败。
- 情境3基线给出的“学习电路工作过程”是带明确删除条件的可选动作。没有分析就须删除，不能直接视为伪造；更稳妥的写法是将需确认的动词放在单独的可选版本。

这些断言能够检查首轮规划的基本结构和诚实边界，但不验证真实完成速度、学员能力增长或就业结果。后续应加入诊断错题、安装连续失败、丢失模型、仅AC曲线、测试平台漏错等跟进情境，并重复生成以观察稳定性。

样本很小：每个情境、每个条件只有一次生成。30个断言也不是30个独立样本。本轮只能描述这6份答复上的差异，不做统计显著性、因果改善、总体稳定性、客户端兼容性或求职效果声明；100%通过也不代表真实工具任务已经完成。
