## 三份实际模型响应与补充回归情境

原 v1.0 三情境、十五项对话检查仍是原始记录。本轮另由执行代理按文件读取新版Skill，对三个独立情境生成完整模型响应；未读取旧评测答案，未安装客户端、联网或运行EDA。三份原始输出以SHA256一致性复制到 [case-1](../evals/v1.1/case-1.md)、[case-2](../evals/v1.1/case-2.md)、[case-3](../evals/v1.1/case-3.md)，没有改写原答复。独立评审结论见 [v1.1行为回归审核](behavior-regression-v1.1.md)。

三个实际情境分别覆盖：企业届别/招聘状态/加分项与12小时时间预算；泰凌微岗位原文强度与6小时无商业工具路线；全部测试通过时的诚实记录及摄氏温度/温升的数值验收。执行中发现的教学资料残留已修复，并做静态回归；不能因此声称三份答复全部由最终修订字节重新生成。NVIDIA的SVA双重语境补充也不计为新增客户端或模型重测。

独立逐条审阅的结论为三例在指定检查范围内均通过，未发现需修改原响应的问题。评审重新计算了9.6+2.4=12、4.8+1.2=6及假设环境25°C时的3/72≈4.17%；不适用项未计为通过。三份公开响应与实际审阅原文SHA256一致。C1职责边界、F3的SVA语境及所有13路线等未被这三例全面覆盖，详见该报告的缺口说明。

以下六类可用于后续真实客户端验收；其列出不代表六次独立模型实验均已执行：

## 维护者运行方式

先运行 `python scripts/validate_release.py` 做内容准备检查，再使用 `python scripts/build_release.py --list-source` 审查待发布文件，最后运行 `python scripts/build_release.py` 生成 ZIP 与 `release/SHA256SUMS-v1.1.0.txt`。源码打包不要求本地存在Word/PPT。需要单独检查Office附件时，备齐成品后另运行 `python scripts/validate_release.py --require-artifacts`。

最终构建仅在完整结构检查通过时开始，先写入本地 `.qa/` 暂存，再发布当前版本的 ZIP。脚本不执行安装、联网、上传 GitHub 或发送消息。哈希清单与 ZIP CRC 通过只证明文件完整性，不是平台认证或工业技术认证。

最终发布构建生成Codex、WorkBuddy和完整源码三个v1.1.0 ZIP。平台包共有21个Skill文件，核心正文一致、参考文件逐字节一致；源码包保留企业资料、3份原始模型响应、讲稿、素材和构建/检查脚本。按作者要求，32页Word和12页PPT作为独立附件，所有Word/PPT/PDF成品均不进入源码包。源码包另排除`.qa/`、旧v1.0产物、历史SHA清单和自身源码压缩包。当前校验值写入 `release/SHA256SUMS-v1.1.0.txt`，Office附件存在时只单独记录其哈希；旧版ZIP/Word及旧版校验清单均保留在作者本地。
